# 00 · 产品定位与范围

## 1. 一句话定位

**Solidify 是一个本地优先的 AI 交付工作台**：把交付顾问的项目文件、工作过程、专业方法和 AI 执行力装进同一个桌面应用，让 AI 以「可调度的同事」而非「聊天框」的方式参与交付工作。

## 2. 从「对话工具」到「工作台」的差别

当前形态和目标形态的核心差异不在功能多少，而在**主体是谁**：

| | 当前：AI 对话工具 | 目标：AI 工作台 |
|---|---|---|
| 中心对象 | 一段对话 | 一个项目（= 一个本地目录） |
| AI 的角色 | 回答者，产出文本 | 执行者，读写文件、调用工具、多步完成任务 |
| 用户动作 | 提问 → 复制结果 | 交办 → 观察过程 → 确认关键节点 |
| 成果去向 | Artifact 面板，手动导出 | 直接落到项目目录，成为下一步的输入 |
| 专业能力 | 写死的 prompt 模板 | 可安装、可版本化、带资源和工具的 Skill |
| 会话结束后 | 记录留在云端库表 | 文件、过程、结论都在你自己的文件夹里 |

一句话：**从「AI 帮我写一段」变成「AI 帮我做完这件事」。**

## 3. 四根支柱

### 支柱一：文件管理

项目的真相在本地文件系统，不在数据库。

- 项目 = 一个用户可见的普通目录，可以用 Finder/资源管理器打开、拖拽、备份、放进网盘或 Git
- 应用内提供文件树、预览、检索，但**不劫持文件**：用户在系统里改了文件，应用要能感知并同步
- 大文件（原始材料、素材、导出物）永远留在本地，不上传

**为什么重要**：这是本地优先相对 SaaS 最大的体验优势和信任来源。用户不会担心"数据锁在别人平台里"。

### 支柱二：项目作业区

一个项目就是一个作业上下文，AI 在这个上下文里工作。

- 项目内聚合：文件 + 对话 + 交付物版本 + 任务队列 + 项目级知识
- AI 的默认工作目录 = 当前项目目录，读写都受限在这个范围内
- 阶段化推进：一个交付项目有明确阶段（调研 → 方案 → 评审 → 交付），每个阶段有产出物清单

### 支柱三：Skill 体系

把交付方法论沉淀成可分发的能力包。

- Skill = 一个目录：`SKILL.md`（说明与工作流）+ `reference/`（按需加载的规范）+ `examples/`（少样本）+ `assets/`（模板资源）
- **渐进式披露**：初始上下文只有 skill 的名称和描述（几百 token），模型判断相关后才主动读取详细规范
- 可安装、可版本化、可导入导出、可共享

### 支柱四：Agent 协作

从单轮问答升级为多步自主执行 + 人在环确认。

- 多轮工具调用循环：模型决定用什么工具 → 执行 → 结果回灌 → 继续推理，直到任务完成
- 全过程可见、可中断、可回溯
- 关键写操作需要人工确认，权限结果统一为 `allow` / `ask` / `deny`
- 后续支持子 Agent 分工：一个主 Agent 拆解任务，派发给专职子 Agent 并行处理

## 4. 目标用户与典型场景

**用户画像**：交付顾问、售前、方案工程师、项目经理 —— 需要在短周期内把零散材料变成结构化交付物的人。

**典型场景（M4 完成后应能一次交办跑通）**：

> 「把 `01-输入材料/` 里的三份客户访谈纪要和一份现状调研，整理成需求规格文档，再基于它出一版给客户领导汇报的方案 PPT，放到 `03-交付物/`。」

这一句话背后：读多个本地文件 → 调用需求分析 Skill → 生成文档并落盘 → 调用演示文稿 Skill → 读取 PPTD 规范 → 生成结构 → 渲染预览 → 视觉自检 → 修正 → 导出 pptx。全程用户只需在关键节点点确认。

## 5. 明确的非目标

写清楚不做什么，比写做什么更能防止范围失控：

| 非目标 | 说明 |
|---|---|
| ❌ 不做通用 IDE / 代码编辑器 | 文件树和编辑器只服务于交付物，不做语法高亮之外的代码智能 |
| ❌ 不做实时多人协同编辑 | 协作粒度是「文件/交付物版本」，不是 CRDT 字符级 |
| ❌ 不做模型训练与微调 | 只做推理侧编排 |
| ❌ 不自研 Agent 编排 DSL | 编排用代码和 Skill 表达，不做可视化流程画布 |
| ❌ 不做移动端 | 桌面优先，Web 端保持可用但功能子集 |
| ❌ PPT 不做动画 | 见 [ADR-0003](04-decisions.md#adr-0003)，预览可有 CSS 动画，导出直接丢弃 |

## 6. 已确定的两个方向性决策

1. **数据主场在本地**，Supabase 从「数据主库」降级为「同步与协作层」。详见 [ADR-0001](04-decisions.md#adr-0001)。
2. **PPT 能力自研**：吸收 PPTD 格式规范与方法论，自己写解析器、渲染器和导出器，不依赖任何外部在线服务。详见 [ADR-0003](04-decisions.md#adr-0003)。

## 7. 成功判据

| 阶段 | 判据 |
|---|---|
| M1 完成 | AI 能连续调用 3 次以上工具完成一个任务，过程可见可中断 |
| M3 完成 | 用户能新建本地项目目录，AI 能读写其中文件，Finder 里的改动能被感知 |
| M4 完成 | 第 4 节的典型场景能一次交办跑通（PPT 可用降级导出） |
| M5 完成 | 生成的 PPT 无需人工调版即可直接给客户，元素不重叠不出血 |
