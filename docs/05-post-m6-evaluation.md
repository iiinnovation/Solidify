# M6 后评估结论

M6 之后没有继续排定的 M7/M8 里程碑。本文件把路线图中两项“以后再评估”的内容收敛为明确边界，避免它们在没有用户场景和验收标准时直接变成新范围。

## 1. 后台执行与关窗续跑

**结论：暂不实现下沉 Rust。**

当前 Agent 循环依赖前端运行时、模型流式连接和用户确认入口。把循环移到 Rust 不能只搬一个线程，还需要持久化运行状态、重连模型流、跨进程传递 ask/abort、恢复未完成工具调用，并重新定义凭据存储。M6 的任务树取消和预算传播已经覆盖当前生命周期；在没有“关窗后继续跑”的明确产品承诺前，下沉会扩大故障面而不增加可验收价值。

再次启动条件：

- 至少一个真实场景要求窗口关闭后仍继续执行；
- 能接受或明确设计桌面端凭据托管、网络断线重连和确认超时语义；
- 先以单 Agent、无子 Agent 的后台任务做垂直切片，再迁移任务树。

首个切片的验收：应用重启后可恢复一个运行快照；正在等待用户确认的工具不会自动执行；停止主运行能终止所有子进程；账本不重复记账。

## 2. 多人协作

**结论：不纳入本地优先版本。**

当前工作区的冲突策略是“本地永远赢”，M6 只解决同一用户、同一任务树内的受限并发。多人编辑需要身份、共享存储、锁或 CRDT、权限模型、离线合并和审计，这不是在现有本地账本上追加一个同步按钮可以完成的能力。

再次启动条件：

- 有明确的共享项目和角色权限需求；
- 先确定服务端存储与同步协议，再定义文件、Artifact、账本三类数据的一致性边界；
- 先做只读共享和显式导入导出，不直接承诺实时协同编辑。

首个切片的验收：两个账户可查看同一项目的版本历史；并发修改不会静默覆盖；冲突有可追溯的解决记录；离线修改重新联网后不会丢失。

## 当前状态

- M6 仍只剩真实客户材料 Demo 的人工验收；自动化覆盖和真实 DeepSeek 子 Agent 并发验收已通过。
- M6 后没有新增正式任务，以上两项均为触发式候选，不进入当前排期。
