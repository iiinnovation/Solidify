# OCR 离线组件包契约（准备阶段）

2026-09-10 更新。`sandbox_exec/package.rs` 与 `package/unpack.rs` 已实现认证及私有解包准备、后端协作取消、分阶段进度及明确清理结果；`installation.rs` 已接入实例级校验作业、IPC、界面和退出等待。尚未实现正式组件安装发布、激活或签名/公证自检。生产发布公钥仍为空，界面禁用校验入口，后端也会在登记作业和读取选择文件之前拒绝。

## 发布文件

发布方提供 `release.json`、`release.json.minisig` 和 ZIP 归档。Minisign 必须使用 prehashed 签名，同时验证原始描述字节与 trusted comment；trusted comment 不提供安装策略。描述字段见 [实施记录](sandbox-execution-implementation.md)，归档与内层清单的 SHA-256 都由已签名描述绑定。生产公钥由应用代码持有，不能来自 renderer、模型、归档或可写配置。

`prepare_package` 先认证描述，再复制归档；签名无效或未配置公钥时，不读取归档、不创建暂存目录。输入归档从同一普通文件描述符流式复制到新建私有目录，并在复制时核对实际大小、哈希和前后元数据。后续只使用该私有副本的已打开描述符，不凭先前验证报告重新打开用户路径。

## ZIP 与清单约束

首版是受限组件格式，不是通用解压工具：

- 单卷 classic ZIP，仅 Stored/Deflate；通用标志仅接受 UTF-8 位，其余位必须为零。不接受 ZIP64、加密、data descriptor、归档注释、前置/追加内容。
- ZIP 只包含普通文件，目录按文件路径隐式创建；不接受目录条目、符号链接、特殊文件、setuid/setgid/sticky 权限。
- 原始 ZIP 目录记录数、本地头、文件名、压缩方法、CRC/大小及数据范围必须一致，局部数据范围完整连续；拒绝隐藏条目、重叠范围和重复条目。解析库按名称建索引后的数量也必须一致。
- 文件名仅使用 ASCII 字母、数字、`.`、`_`、`-`、`/`，最长 240 字节、最多 8 段；拒绝绝对路径、反斜杠、空段、`.`/`..` 段、大小写文件别名和文件/目录冲突。
- 根目录必须有 `manifest.json`，其字节先通过发布描述中的哈希验证，再解析为 `ComponentManifest`。归档内容严格等于此清单文件加 `manifest.files`，不允许遗漏或额外文件；清单不得把自身列为组件文件。
- 清单的版本、平台、架构必须与发布描述一致。简体中文、英文语言包、转换程序及声明的 PDF 程序仍由共用组件验证器复核。
- 语言包必须同时登记 `languageVersions` 和对应的哈希文件项；未登记的 `.traineddata` 也拒绝。验证器在哈希校验的同一描述符上读取内置 config，从固定 `chi_sim+eng` 递归检查 `tessedit_load_sublangs`，每个间接依赖也必须有文件、版本及正确哈希。循环引用按已访问集合终止，不重复扩展读取权限。
- 模型容器暂只接受 classic little-endian 格式，目录项 1 至 64 个、偏移有序且在文件内；config 至多 64 KiB、UTF-8、每行至多 254 字节。语言名限定 1 至 64 个 ASCII 字母/数字/下划线，子语言列表使用 `+`；重复声明、路径、排除语法、值末尾空白和其他歧义配置拒绝。此限制避免与 Tesseract 的定长读行和字符串参数语义不一致，不是通用 traineddata 格式支持。
- 归档最多 512 MiB；清单最多 64 KiB；最多 240 个载荷文件（加清单共 241 项）；ZIP 中央目录最多 256 KiB；载荷展开合计最多 512 MiB。私有副本与展开载荷同时存在，准备阶段磁盘占用上界约 1 GiB 加文件系统开销。
- 展开逐文件检查实际字节数和 SHA-256，最多读取一个额外字节检测超量，不把超量字节写入磁盘；不只相信 ZIP 声明的解压大小。ZIP CRC 错误也拒绝。

这些限制是明确的包格式约束；正式发布包若不满足，需要重新评估，不能让安装器静默放宽。

## 私有目录与结果

准备父目录由安装器提供，必须是规范化的绝对路径，Unix 下为当前用户所有且组/其他用户无访问权限；非 Unix 尚未实现 ACL 验证，准备入口保持不可用。新建随机准备目录和所有子目录为 `0700`。普通数据为 `0400`，只有清单中固定转换程序为 `0500`；归档自带权限不直接恢复。

准备成功返回仅由后端持有的 `PreparedPackage`，不是 `SandboxRuntime` 能力。成功后删除归档副本，保留已认证清单和载荷供后续安装检查；准备失败或取消时关闭本次文件描述符并显式清理私有目录，不删除来源归档或其他准备目录。清理失败返回 `stop_failed`，不能以原先的 `cancelled` 掩盖未回收内容。成功对象可调用 `discard()` 获取明确清理结果；析构仅作兜底，失败记录日志，不能用于向用户确认回收成功。清单哈希复核后再次调用共用组件验证器。全程没有下载、启动转换器或写入用户文档。

下一步安装器仍须实现：许可证和正式包评估、macOS 发行身份与公证检查、真实隔离 probe、安装目录不可变与原子发布、升级回滚，以及对应的正式安装向导。校验作业登记、取消/进度 IPC 和退出等待现已接入；进程崩溃遗留目录回收、持久化恢复和空间不足的专门提示仍未完成。

## 校验作业与界面

当前界面入口是“校验组件包”，位于任务的 OCR 组件状态中。用户分别选择发布描述、签名和 ZIP，文件选择使用现有桌面对话框；没有下载或模型传入命令。未配置发布公钥、平台不支持、应用退出、已有活动作业或未清理残留时禁止发起新的校验。

`ocr_installation_status`、`ocr_prepare_package`、`ocr_cancel_preparation`、`ocr_retry_preparation_cleanup` 是桌面 IPC，没有注册为模型工具。开始仅接受三个文件路径，不接受公钥、组件版本或“已验证”标记；描述/签名分别限 64 KiB/4 KiB，按同一普通文件描述符读取并拒绝末级链接、目录与 FIFO。状态返回作业 ID、阶段计数和结构化错误，不返回文件路径、归档/描述内容或内部准备目录。

每个应用实例至多保留一个活动作业和最近一次结果，以随机 ID 绑定取消和清理请求；旧 ID 不可操作后来的作业。文件读取和准备在后台线程执行，不在持有状态锁时做文件 I/O。取消和退出共用状态锁标记；返回前在同一锁内决定终态，取消后的晚到成功不会被记作通过。每个作业创建自己的 `solidify-ocr-install-UUID` 私有临时目录；只有该作业实际创建并持有的根目录可被本次或重试清理。

校验成功后调用 `discard()` 并清理作业目录，最终状态为 `validated`，界面明确显示“组件包校验通过，未安装”。不保留可激活能力或已验证路径凭证；将来的真实安装仍须重新取得已认证私有副本并完成安装自检，不能复用这次结果跳过认证。配置发布信任以后，作业会在描述认证前创建自己的空私有根目录；内层准备流程仍在签名认证后才读取归档或创建载荷。

作业状态包括 `running`、`stopping`、`cleaning_up`、`validated`、`cancelled`、`failed`、`cleanup_failed`、`cleaned`。准备失败、取消和异常展开均执行回收；清理失败保留已知目录并阻断新作业。用户可重试清理，成功后进入 `cleaned`。应用关闭/重启会拒绝新作业、取消活动校验并等待清理，清理失败阻断退出；再次关闭会重试已知残留。不会因为关闭窗口就递归扫描、接管其他实例目录。

界面按当前快照串行轮询，卸载停止查询；重新挂载可读取本实例仍在运行的作业，旧响应不能覆盖新视图。查询失败时清除未确认的状态并禁用开始，不假称校验结束。校验通过不会激活 OCR，也不会重试、领取或改写文档任务。

作业和待清理目录引用目前只保存在本实例内存中；应用被强制结束后的目录不会自动采用或删除，跨进程恢复尚待实现。实例之间没有共享正式安装目录，因此这里的互斥不是将来原子安装/升级所需的跨实例安装锁。

## 准备取消与进度

`prepare_package_with_progress` 接受后端提供的检查和进度回调，旧 `prepare_package` 保留无回调包装。检查回调可读取安装作业的取消标志或截止时间，返回已有结构化错误；回调本身应快速、非阻塞，不接收模型命令、路径或信任公钥。签名认证仍先于归档读取和目录创建，进度接口不能跳过认证。

| 阶段 | 进度含义 |
|---|---|
| `authenticating` | 发布描述认证；未知总量 |
| `copying_archive` | 已复制字节 / 已签名归档字节数 |
| `inspecting_archive` | ZIP 目录、条目与内层清单检查；总量未知 |
| `extracting_files` | 载荷已写字节 / 声明载荷总字节；已通过哈希并封存的文件数 / 总文件数 |
| `verifying_components` | 对完整落盘组件重新校验；总量未知 |
| `cleaning_up` | 失败或取消后的必要清理；不因取消标志而跳过 |

计数在阶段切换时重置，只在同一阶段内单调增加。载荷字节总量不含另存的 `manifest.json`。复制或展开达到 100% 仍可能在哈希、CRC、落盘同步或组件复核时失败，因此没有把进度定义为“安装完成”或运行时就绪。

复制和解压按最多 64 KiB 的数据块检查取消，ZIP 目录逐条检查，最终组件哈希读取也按最多 64 KiB 检查。进度回调返回后再次检查，且在最终复核与归档副本清理之后、返回 `PreparedPackage` 之前保留检查。取消和截止时间错误在清理成功后原样返回；若清理失败则以 `stop_failed` 为准。

这是协作取消，不能中断正在阻塞的文件系统调用、`fsync` 或删除操作，不提供取消延迟的硬实时保证。检查回调不是发布事务锁；后续安装器仍须在作业所有权保护下执行最终发布验收。清理失败留下的内容也不由本接口自动跨进程扫描删除。

## 可复现证据

```sh
cargo test --offline --manifest-path src-tauri/Cargo.toml --lib sandbox_exec::package
```

17 项包测试覆盖认证拒绝、真实签名的测试归档完整准备链路、原路径替换后仍使用私有副本、清单与文件篡改、缺失/额外文件、链接/FIFO/特殊权限、路径冲突、ZIP 目录与本地头不一致、超量解压、失败清理和并行准备目录隔离。新增测试还覆盖各准备阶段及复制/解压中途取消、最终复核后的取消/超时、真实权限故障下清理失败、进度语义与显式丢弃。另有组件哈希单测验证取消后没有读取大文件剩余内容。

`package/fixtures/test-release.*` 是明确面向 macOS x86_64 的非生产夹具，载荷为文本假程序和最小语言容器，不能执行 OCR。签名使用 [RFC 8032 §7.1](https://www.rfc-editor.org/rfc/rfc8032#section-7.1) 公开测试向量的密钥，**没有任何发布信任价值**；测试公钥只在私有单测中注入，生产入口仍拒绝该包。其他平台验证这份签名后应拒绝平台/架构不符，不外推为跨平台安装通过。

语言夹具现使用最小容器头及非模型字节，以覆盖依赖检查入口，仍不能执行识别。夹具可用 Python 标准库和 OpenSSL 3 重新生成，正常 Rust 测试不依赖签名程序：

```sh
python3 tools/generate-ocr-package-test-fixture.py --openssl /absolute/path/to/openssl-3
```

此证据证明安装准备的认证与文件处理边界，不证明正式 OCR 包、代码签名/公证、生产激活或识别质量达标。

校验作业新增 5 项后端测试，覆盖未配置公钥时零登记/零读取、活动作业互斥、旧 ID、晚到取消、退出等待、实例隔离、异常回收、真实权限故障下清理阻断及重试、描述读取上限和特殊文件拒绝。它们与已有签名准备链路测试分层验证；成功作业状态测试使用内部受控操作，不向生产信任列表注入测试公钥。

本轮全量 Rust 库测试 157 通过、16 忽略；前端界面、IPC 和退出提示相关测试 12 通过，TypeScript 检查与应用二进制离线构建通过。Playwright 在 1280×900 与 375×812 下检查了禁用、开始、进度、取消、清理重试和“通过但未安装”状态，长文件名无横向溢出。浏览器验证使用真实组件和模拟 IPC，不是已签名组件安装或 Tauri 桌面端到端验收。构建保留现有辅助入口的 dead_code 警告。

`languageVersions` 的运行时返回值覆盖固定主语言及其所需的传递依赖，顺序以主语言在前且去重。它记录经校验的所需模型来源，并不是逐字识别时模型贡献的追踪；模型内容是否能被引擎成功加载仍须真实 probe 和诊断检查，不能仅凭容器/config 检查就激活组件。
