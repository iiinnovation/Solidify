# OCR 预处理受控对照

日期：2026-09-10。对应 [OCR 开发态质量集](ocr-quality-evaluation.md)。本实验只在测试模块运行，没有改变生产 OCR 的默认参数、组件信任或激活状态。

## 目的与固定输入

检验字段裁切、去表格线能否改善上一轮金额误读，并明确每种策略相对于原图的改善和退化。使用原质量集全部 32 张 PNG：3 种字体 × 2 种版式 × 4 种金额的 24 张清晰图，加 8 张 PingFang 配对模糊图。本轮不包含 JPEG、扫描 PDF、其他字号或真实业务扫描，不把这些相关配置作为 32 份独立业务文档。

固定使用 Tesseract 5.5.3 和上一轮提交/哈希锁定的 tessdata_best 中英文模型，`chi_sim+eng`、OEM 1。原图逐文件 SHA-256 必须与上一轮固定模型报告一致，生成器也必须哈希一致；每次原图识别还会和上一轮去空白后的文本逐字对照。先报告基线是否复现，再解释处理策略的变化。

## 方案与评分

每张图运行以下五组，共 160 次识别。各组事先固定，不按具体金额或观察到的结果选择参数，也不将多种策略对不同样本的最好结果合并为一个策略成绩。

| 报告中的 variant | 输入变换 | PSM | 用途 |
|---|---|---:|---|
| original | 原始 PNG 字节 | 3 | 复现上一轮基线 |
| rgb-reencode | 转 RGB8 后重新编码 PNG，保留全部像素位置 | 3 | 单独控制编码、alpha 和图片元数据变化 |
| remove-lines | 在 RGB8 图上检测并擦除长直线，再编码 PNG | 3 | 和重新编码组比较去线效果 |
| oracle-row-crop | 去线后裁切已知金额行 | 3 | 和去线组比较裁切效果 |
| oracle-row-crop-psm7 | 同一裁切图 | 7 | 和裁切 PSM 3 比较分行模式效果 |

PSM 3/7 的含义已核对本机固定 Tesseract 的 `--help-psm`：分别为自动分块和将输入视为一行文本。实验通过现有 worker/监督器在真实 Seatbelt 中运行，仅测试代码可更改该参数。

去线只查看像素，不读取答案：三个 RGB 通道都低于 128 视为深色；水平连续段至少 600 px，垂直至少 100 px，相邻检测扫描线组成的带宽至多 6 px，擦除时扩大 3 px 覆盖本批模糊图的线边。粗色块不按直线清理，也不擦白整个行列。普通文本样本必须检测为零像素修改；表格样本要求修改量在 5,000 到 80,000 像素之间。此参数针对 1600 × 700 的合成图，不能直接用到任意尺寸扫描，交叉文字、倾斜线、断线仍未验收。

裁切坐标固定为左上原点 `(85, 200)`、大小 `1430 × 100`，保留“合同金额”标签和金额值；来自生成器的已知几何位置。边缘 8 px 不得含深色墨迹且总墨迹必须非空，防止明显切字或空白图。**这是已知位置的诊断实验，不是自动金额定位功能**。裁切图不包含其他三条控制短句，因此其 `missingControlLines` 为 null，不能据此宣称整页文本完整。

主指标继续使用原先的整行精确金额评分：只去空白，数字、币种、标点、单位和重复行均保留约束。另附 `currencyWidthEquivalent` 诊断指标，只将 `￥` 映射为 `¥`，不调整数字、分隔符、单位或其他币种误字；此指标不替代严格门槛，也不代表通用金额语义正确。每种方案都分别记录相对原图的改善/退化。

普通单测覆盖短横线、独立文字笔画、粗色块保留以及仅币种宽度诊断不会放过丢数字/多数字。生成图片测试检查了全部 32 张输入，已查看去线后的模糊表格及裁切后的中文大写、数字金额。初始去线参数仅扩展 1 px，检查时发现模糊线边残留，改为 3 px 并重新生成检查；实际 OCR 对照使用的是最终参数。

## 完整结果

全部 160 次隔离进程均以 0 退出，逐次暂存输入哈希及 work 目录无遗留检查通过；32 张原图的去空白文本全部复现上一轮基线。最终质量断言失败，测试退出码 101：没有一种固定预处理在全部样本上通过严格金额门槛。整项测试 439.10 秒，包含生成、组件准备、每次组件复核及进程启动，不是纯识别速度基准。[完整机器可读报告](ocr-quality/2026-09-10-preprocessing-pinned-best.json) 已保留。

| 固定策略 | 金额严格命中 | 仅统一币种宽度后的命中 | 相对原图严格改善 / 退化 | 相对原图宽度等价改善 / 退化 |
|---|---:|---:|---:|---:|
| 原图 PSM 3 | 8/32 | 14/32 | — | — |
| 只重新编码 PSM 3 | 8/32 | 14/32 | 0 / 0 | 0 / 0 |
| 去线 PSM 3 | 9/32 | 14/32 | 1 / 0 | 1 / 1 |
| 去线后已知金额行裁切 PSM 3 | 9/32 | 14/32 | 1 / 0 | 1 / 1 |
| 同一裁切图 PSM 7 | 9/32 | 14/32 | 1 / 0 | 1 / 1 |

原图、重新编码、去线三种完整图的控制短句均为 96/96 命中；裁切组不评估已移出画面的控制短句。重新编码组与原图去空白后的全文全部一致，因此本批没有观察到编码本身带来的识别差异。

改善与退化出现在不同样本，不能只看总命中数：

- 去线修复了 PingFang 模糊表格里原先漏掉的“一百万元”。但再次裁切后该样本又不能正确识别；局部获益并未随处理步骤累积。
- 裁切修复了黑体清晰表格的“壹佰万元整”，金额大写组从原图 1/8 变为 2/8；普通数字小数组仍为 3/8。换成 PSM 7 没有额外的金额命中提升。
- 三种预处理都将 PingFang 模糊表格中的 `¥98,765.40` 读成 `¥098,765.40`，多识别一个前导 `0`。原图严格评分已因 `￥`/`¥` 宽度差异失败，因此只看严格改善/退化会隐藏这次数字文本退化；附加指标揭示了它。前导零不应被夸大为本例数值金额改变，但也不能在原文提取中默默补入。
- 去线组的中文小写金额为 5/8、大写 1/8；两个裁切组为小写 4/8、大写 2/8。三种策略的币种宽度等价项均从 6/8 降为 5/8，没有一套统一策略覆盖不同写法。

结论：在当前样本和模型组合下，去线/裁切/单行分割只提供局部改善，同时产生新的数字文本错误。没有据此增加默认预处理、挑选每项最好结果或放宽旧基线。下一步先核查并补全下面发现的固定模型隐式依赖及实际来源记录，重新做同样本对照，再决定是否继续预处理或评估其他引擎；仍需扩展数值、字号及真实扫描，不能把当前结果外推到真实文档。

## 模型诊断范围

保留原始 stderr 后发现当前开发组件的另一个限制：固定 `chi_sim.traineddata` 的内置配置包含 `tessedit_load_sublangs chi_sim_vert`。通过本机 `combine_tessdata -e` 从同一份已固定哈希的模型提取 config，已核对该项。开发组件构造器只复制并登记 `chi_sim` 和 `eng`，因此转换器会输出缺少 `chi_sim_vert.traineddata` / `Failed loading language 'chi_sim_vert'`，但退出码仍为 0，并返回识别文本。

全部 160 次运行均有这项诊断。另行提取的宿主原语言包 config 没有声明该子语言；不能把固定模型的发现笼统套用到两套模型。这轮原图和所有预处理使用同样的组件组合，不在中途增加语言包或关闭这项配置。诊断不作为图像预处理效果，也不能据此断言竖排子语言缺失就是横排金额误读的根因。此前生产管线已将非空诊断转为准确性警告；它不等于完整模型依赖已通过验收。正式组件自检还需检查模型隐式子语言依赖，补齐后的效果需要独立对照，并如实记录实际加载模型的来源。

应用二进制离线构建通过（保留既有 dead_code 警告）；最终代码的沙箱模块普通测试 51 通过、12 忽略，包含新增的两项评分/去线保护测试。处理后图片生成检查单独执行通过，覆盖全部 32 张 PNG；随后真实矩阵完成并按质量门槛失败。`rustfmt --check` 和 `git diff --check` 通过。本轮没有修改生产逻辑，也没有重跑全量 Rust、监督故障矩阵或桌面流程，不能把模块回归记作全量/产品验收通过。

## 复现

只生成处理后的图片供检查，无需启动 OCR：

```sh
SOLIDIFY_TEST_OCR_ARTIFACTS=/absolute/path/to/empty-private-directory cargo test --offline --manifest-path src-tauri/Cargo.toml --lib inspect_chinese_ocr_preprocessing_fixtures -- --ignored --nocapture
```

当前代码已增加模型依赖检查，不能再构造缺少 `chi_sim_vert` 的固定模型组件。下面命令运行补齐依赖后的新对照，三个模型的固定来源与前后比较规则见 [模型依赖补全对照](ocr-model-dependency-evaluation.md)；本页上面的历史结果与旧 JSON 保留。

先构建应用，在获授权的外层执行真实隔离对照。报告路径必须不存在，报告完成后才检查质量门槛；某次进程执行失败则停止，不能把未完成报告当作完整实验。单进程 wall 60 秒、CPU 30 秒、输出 64 KiB；转换阶段整轮检查 600 秒预算，Swift 生成及组件准备不由此回调强制中断。

```sh
cargo build --offline --manifest-path src-tauri/Cargo.toml --bin solidify
SOLIDIFY_TEST_BEST_TESSDATA=/absolute/path/to/pinned-models SOLIDIFY_TEST_OCR_REPORT=/absolute/path/to/new-preprocessing-report.json cargo test --offline --manifest-path src-tauri/Cargo.toml --lib live_chinese_ocr_complete_model_preprocessing_matrix -- --ignored --nocapture
```

报告包含每次原始/处理后 SHA-256、已擦除像素数、裁切区域、参数、原文、诊断输出、两个金额指标、完整图控制短句、模型哈希、代码哈希、改善/退化及耗时。测试要求至少一种固定预处理策略在全部 32 张图上通过严格金额指标；即使将来通过，也不替代真实文档定位和完整任务验收。
