# OCR 开发态质量对照

初始记录：2026-09-07；固定模型对照复测：2026-09-09；受控质量集扩展：2026-09-10。此记录不代表生产组件安装、激活或完整文档任务验收通过。

## 样本和环境

`tools/generate-ocr-fixture.swift` 用 macOS 系统字体生成同一内容的 PNG、JPEG 和两页纯图片 PDF；没有内嵌文本层、业务文档或下载字体。固定短句为“项目验收报告”“中文识别测试”“合同金额一百万元”和“SOLIDIFY OCR VALIDATION”。图片已人工查看，“百”字输入正确。

环境：macOS 26.6.2 / x86_64、Tesseract 5.5.3、Poppler 26.09.0。开发组件复制到私有临时目录，解析已安装二进制的 LC_RPATH 后重定位具体动态库并 ad-hoc 签名；未改变宿主安装，也未扩大沙箱读取授权。该 Poppler 二进制声明最低 macOS 26.0，不据此承诺较旧系统兼容。

## 原语言包的真实流程与质量

PNG、JPEG、两页 PDF 的流程、源哈希、页码、双语言来源、准确性告警及 PDF 中间图片清理均通过检查；严格文本质量基线失败，仍保留失败断言，不替换预期文本以适配误读。

- PNG/JPEG 将“一百万元”识别为“一自万元”。
- PDF 两页均将该金额识别为“一正万元”，并误识别“中文识别测试”中的“中”。
- 完整流程最近一次耗时分别约 11.7 秒、1.1 秒、18.2 秒，包含组件校验/进程启动，不是纯推理性能基准。

固定同一份样本，在相同沙箱内进行 16 组受限实验（整轮最多 300 秒、单进程最多 60 秒）。以下为每页 4 条短句的精确命中数；不是字符准确率，也不能外推到真实文档集合。

| 输入 | PSM 3 | PSM 6 | 两种语言配置的差异 |
|---|---:|---:|---|
| PNG | 3/4 | 3/4 | chi_sim 与 chi_sim+eng 均未识别对金额 |
| JPEG | 3/4 | 3/4 | 同上 |
| PDF 150 DPI | 2/4 | 3/4 | 金额始终错误，PSM 6 修复了测试短句 |
| PDF 300 DPI | 3/4 | 3/4 | 金额始终错误；PSM 6 出现“一特万元” |

结论：这些参数没有消除金额误读，没有据此修改默认流程。参数实验完成不等于质量基线通过。

## 固定官方模型对照

选择 [Tesseract 官方 tessdata_best](https://github.com/tesseract-ocr/tessdata_best) 作开发态对照。该仓库提供 LSTM 模型并声明 Apache-2.0 许可，参见其 [README](https://github.com/tesseract-ocr/tessdata_best/blob/e12c65a915945e4c28e237a9b52bc4a8f39a0cec/README.md)。提交固定为 `e12c65a915945e4c28e237a9b52bc4a8f39a0cec`，测试只接受以下 SHA-256：

- chi_sim：`4fef2d1306c8e87616d4d3e4c6c67faf5d44be3342290cf8f2f0f6e3aa7e735b`
- eng：`8280aed0782fe27257a68ea10fe7ef324ca0f8d85bd2fd145d1c2b560bcb66ba`

模型仅下载到临时目录；测试再次复制并校验，不替换已安装语言包。用 `SOLIDIFY_TEST_BEST_TESSDATA` 显式指定该目录，此变量仅在 macOS 测试模块生效，不用于生产配置或模型工具输入。

2026-09-09 重新构建应用二进制后，固定官方模型真实隔离流程测试完成，严格质量基线失败（退出码 101）。所有文件的流程完整性、源哈希、页数/页码、双语言来源、准确性告警及 PDF 中间图片清理断言通过；最后汇总文本质量失败，未放宽预期文本。

| 输入 | 每页短句精确命中 | 金额识别结果 | 其他误读 | 流程耗时 |
|---|---:|---|---|---:|
| PNG | 3/4 | 一自万元 | 无缺失短句 | 16,390 ms |
| JPEG | 3/4 | 一自万元 | 无缺失短句 | 1,954 ms |
| 两页 PDF | 两页均 2/4 | 两页均一正万元 | 两页均将“中文识别测试”的“中”读为 `inl` | 21,280 ms（两页合计） |

整项测试耗时 62.24 秒，包含样本生成、临时组件准备与校验；表中为各文件流程报告的耗时，不是纯推理性能基准。去除空白后，4 页共命中 10/16 条短句，金额短句为 0/4；两张 PDF 页面内容相同，不算独立样本。

复核宿主模型 SHA-256：chi_sim 为 `a5fcb6f0db1e1d6d8522f39db4e848f05984669172e584e8d76b6b3141e1f730`，eng 为 `7d4322bd2a7749724879683fc3912cb542f19906c83bcc1a52132556427170b2`，均与上述固定模型不同。测试复制后再次验证固定模型哈希，因此此次确实使用了不同模型文件。

结论：在当前样本和默认流程下，这套 tessdata_best 未消除原语言包的金额误读，也未修复 PDF 的中文短句误读。现有证据不能确定根因，不能外推为所有模型或预处理均无效；未修改生产参数、已安装语言包或激活状态。后续需要包含不同字体、金额写法、版式及模糊扫描的独立质量集，再评估预处理或其他识别引擎，并完成完整任务验收。

## 受控质量集扩展（2026-09-10）

新增 `tools/generate-ocr-quality-corpus.swift`，保留原生成器及原来的失败断言。使用系统内置 PingFangSC-Regular、STSongti-SC-Regular、STHeitiSC-Light 三种字体，固定 52 px、1600 × 700 图片；生成前逐字核对中文和金额字符没有字体回退。普通四行文本和有横纵线的表格各包含四种金额：`一百万元`、`壹佰万元整`、`1,234,567.89元`、`￥98,765.40`。

共 24 个清晰 PNG 配置、8 个 PingFang 配对模糊 PNG，以及一个包含三种字体各一页的纯图片 PDF，共 33 个文件、35 页。模糊使用 CPU 7 × 7 二项式卷积（权重为 `[1,6,15,20,15,6,1]` 的外积、除数 4096，约 1.225 px 标准差）；PDF 页面来自三张已有清晰 PNG，按默认流水线 150 DPI 渲染。已查看三种字体及模糊、表格、金额生成图。这些是控制变量的合成配置，模糊和 PDF 是配对对照，**不能把 35 页当作 35 份独立真实业务文档**。

测试 `live_chinese_ocr_quality_corpus` 逐文件使用现有隔离转换管线，复核来源哈希、方法、路径、执行 ID、完整性、页码、双语言来源、准确性告警及中间图片清理。转换阶段检查整轮 600 秒预算，各文件沿用默认 120 秒限制；样本生成/组件准备不是由此回调强制中断。所有页面评分完成并输出报告后才触发严格质量失败，不在第一处金额误读时丢掉后面的对照。

评分仅去除空白：金额必须匹配整行金额值，或匹配带完整“合同金额”标签的整行，且只出现一次；数字、标点、币种、单位均不替换、不补齐。三条非金额控制短句按去空白后的精确子串命中统计。**这是文本严格命中指标，不是金额数值准确率**；例如 `￥`（U+FFE5）变成 `¥`（U+00A5）也计为失败，但应与丢失数字的错误分开分析。新增普通单测覆盖多余数字、单位缺失、币种差异及重复正确行不会获得通过。

### 同样本模型对照结果

原语言包和固定 tessdata_best 均完成全部 33 文件/35 页的隔离流程与完整性检查，最终严格质量断言均失败（退出码 101）。整项测试分别耗时 98.99 秒、140.95 秒，包含 Swift 样本生成、临时组件重定位、校验、启动、渲染和识别，不能当作纯推理性能基准。

| 配置 | 原语言包金额整行命中 | tessdata_best 金额整行命中 | 原语言包控制短句命中 | tessdata_best 控制短句命中 |
|---|---:|---:|---:|---:|
| 清晰 PNG（24 配置） | 4/24 | 5/24 | 64/72 | 72/72 |
| PingFang 配对模糊 PNG（8 配置） | 2/8 | 3/8 | 24/24 | 24/24 |
| 三字体配对扫描 PDF（3 页） | 2/3 | 2/3 | 5/9 | 7/9 |
| 合计（含相关对照） | 8/35 | 10/35 | 93/105 | 103/105 |

同时命中金额和三条控制短句的页面分别为 6/35、8/35。完整逐页预期、原始文本、命中、来源 SHA-256、语言包哈希和耗时已保存到 [原语言包报告](ocr-quality/2026-09-10-host.json) 和 [固定模型报告](ocr-quality/2026-09-10-pinned-best.json)。两轮生成器、manifest 哈希相同，32 张 PNG 的逐文件 SHA-256 全部相同；PDF 的三页内容按相同生成定义配对，不要求含生成时间元数据的 PDF 文件哈希相同。固定模型在复制后再次通过前述 SHA-256 检查。

只看 24 张清晰 PNG，金额写法的差异如下：

| 金额写法（各 3 字体 × 2 版式） | 原语言包 | tessdata_best |
|---|---:|---:|
| 一百万元 | 3/6 | 3/6 |
| 壹佰万元整 | 0/6 | 0/6 |
| 1,234,567.89元 | 1/6 | 2/6 |
| ￥98,765.40 | 0/6 | 0/6 |

具体观察与边界：

- 字体和版式存在交互：清晰 PNG 的 PingFang、宋体、黑体金额命中分别为原模型 0/8、2/8、2/8，固定模型 1/8、2/8、2/8。两套模型都把 PingFang 的“一百万元”读成“一自万元”；宋体两种版式均读对该值，黑体普通行读对而表格误读。不能据此把错误归结于单一字体。
- 大写金额在三种字体的清晰输入中均未通过；固定模型仍有“索个万元整”“喜佰万元整”等实质性替字，原模型还会输出拉丁字母串。错误不局限于原基线的“百”字。
- 模糊对 PingFang 普通行的两种中文金额都有改善，表格却没有对应改善；固定模型甚至漏掉模糊表格的“一百万元”金额单元格。原模型将清晰数字金额读成 `1234,567.89元`，模糊后变成 `234,567.89元`，丢掉首位 `1`。固定模型能读对这一对数字普通行，但其他字体/表格仍有分隔符误读。**不能把此次模糊处理直接设为默认预处理**。
- 币种项单独解释：8 张币种 PNG 中，原模型 7 张、固定模型 6 张仅把 `￥` 转为 `¥`，数字仍为 `98,765.40`；其余存在 `立` 或 `Y` 替字。此处保留严格失败，但不把纯宽度差异表述为数值识别错误。即使将来另设语义等价指标，原始严格指标和原文仍应保留。
- PDF 两套模型的金额都是 2/3 命中，失败字体却不同；固定模型下 PingFang 为“一正万元”，宋体、黑体金额正确但“中文识别测试”仍误读。没有出现覆盖全部字体/版式/金额的稳定方案。

结论：扩展样本已证明误差分布受字体、版式、金额写法及图像处理共同影响。固定模型改善了部分控制文本和数字金额，但没有通过金额质量门槛。下一步应保持这些分组及原失败基线，先做同样本的字段裁切/去表格线等受控对照，并加入不同数值、字号和真实扫描样本，再评估其他引擎；不能根据这组短句挑选单项最优输出并声称质量已通过。生产参数、组件信任及激活状态均未改变。

本轮工程验证：应用二进制离线构建通过；新增评分单测通过。Rust 全量库测试为 142 通过、1 项既有文件监听测试超时、10 忽略；该文件监听测试单独复测通过，未改动期限或断言，也未把本次全量结果改记为全绿。受限 runner 内首次真实 OCR 无法完成转换，外层获授权后才得到上述有效报告。生成器早期 CoreImage/OpenCL 模糊实验产生无效黑图，已改用上述 CPU 卷积并重新检查；黑图未进入两份结果报告。`git diff --check` 通过。

当前固定模型测试要求目录中同时提供同一提交的 `chi_sim`、`eng`、`chi_sim_vert`，并逐文件核对固定哈希；缺少隐式依赖会在识别前失败。固定模型的历史质量报告保留，当前代码产生的报告标识为 `pinned-best-complete-dependencies`。来源与独立复测见 [模型依赖补全对照](ocr-model-dependency-evaluation.md)。

先构建 `solidify` 二进制，再在获授权的外层执行真实 Seatbelt 测试：

```sh
cargo build --offline --manifest-path src-tauri/Cargo.toml --bin solidify
cargo test --offline --manifest-path src-tauri/Cargo.toml --lib live_chinese_png_jpeg_and_two_page_scanned_pdf -- --ignored --nocapture
cargo test --offline --manifest-path src-tauri/Cargo.toml --lib live_chinese_ocr_parameter_matrix -- --ignored --nocapture
SOLIDIFY_TEST_BEST_TESSDATA=/absolute/path/to/pinned-models cargo test --offline --manifest-path src-tauri/Cargo.toml --lib live_chinese_pipeline_with_pinned_best_models -- --ignored --nocapture
```

第二条和第四条当前均是保留的失败质量基线；第三条只证明参数矩阵执行完毕，不证明识别正确。不要把默认测试中跳过这些真实平台测试的结果当作 OCR 质量通过。

扩展质量集同样需在获授权的外层执行。报告路径必须是尚不存在的绝对路径，失败基线也会保留已完成的全量评分；流水线提前失败时应查看测试日志，不能把空报告当作质量结论。模型参数继续只在测试模块生效。

```sh

SOLIDIFY_TEST_BEST_TESSDATA=/absolute/path/to/pinned-models SOLIDIFY_TEST_OCR_REPORT=/absolute/path/to/new-best-report.json cargo test --offline --manifest-path src-tauri/Cargo.toml --lib live_chinese_ocr_quality_corpus -- --ignored --nocapture
```
