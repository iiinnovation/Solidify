# Solidify PPTD support profile

Read this together with `pptd.md`. The latter is the complete upstream format
specification; this file describes the subset currently generated and exported
by Solidify.

The manifest uses YAML:

```yaml
version: v2
title: Example
size: [960, 540]
theme:
  colors: { bg: '#ffffff', text: '#111827', accent: '#2563eb' }
  textStyles: { title: { fontSize: 32, bold: true, color: '$text' } }
pages: [pages/01.page]
```

A page contains `pageType`, optional `background`, and `elements`. Every
element has a unique `elementId`, an `elementType`, and
`[x, y, width, height]` bounds. The generated subset supports text, shape,
image, line, icon, table, and chart elements. Resource paths must be relative
paths inside the project.

The editable PPTX exporter currently preserves only these `shapeName` values:
`rect`, `ellipse`, `roundRect`, `triangle`, and `arrow`. Use `line` with
`points`/`viewBox` and `endArrow` for connectors. Other names from the full
upstream shape taxonomy degrade to rectangles and must not be generated by the
automatic pipeline.

Chart elements use `chartType`, `data`, `xKey`, `yKey`, and optional `series`.
Bar, line, area, pie, doughnut, scatter, bubble, and radar export as editable
PowerPoint charts. Waterfall, heatmap, treemap, sunburst, sankey, and
candlestick render in previews and export as static images with a degradation
report.

The current exporter does not preserve custom geometry paths, embedded fonts,
element animations, or slide transitions. Do not generate unsupported fields
merely because they exist in the full upstream specification.

The Artifact panel accepts a self-contained multi-file bundle
`{"manifest":"...","pages":{"pages/01.page":"..."},"media":{}}` or inline
PPTD YAML containing `pages[]`.
