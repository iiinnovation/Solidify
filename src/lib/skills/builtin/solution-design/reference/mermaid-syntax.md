# Mermaid 架构图规范

## 语法

架构图使用 `flowchart TB`。节点 ID 只使用英文、数字和下划线，中文放入 `A["中文标签"]`。子图使用 `subgraph layer_id["中文名"]`，不要使用未转义的中文 ID。

## 布局

- 简单方案控制在 5-12 个节点、3-5 个分层；没有内容的层不要画。
- 分层顺序遵循“用户/渠道 → 接入 → 业务 → 数据/外部依赖”，主链路保持自上而下。
- 每个节点只写名称或核心职责，不在节点中放长段说明。
- 外部系统集中放入一个独立子图，不要混入内部应用层。
- 优先减少边：相同调用关系可以连接到聚合节点，避免全连接和交叉线。

## 提交检查

不得有孤立节点、同义重复节点、反向主链路或无解释的双向依赖。图中每个组件都应在方案正文中说明职责，正文中的关键组件也必须能在图中找到。
